# greatsoftware.dev

The Great Software company site. **Astro 7 + Tailwind v4**, static output to `dist/`, deployed to
GitHub Pages on every push to `main` via `.github/workflows/deploy.yml` (Node 22). Custom domain
`greatsoftware.dev` (CNAME in `public/`).

## Layout

- `src/pages/*.astro` — routes (`/`, `/about`, `/contact`, `/privacy`, `/terms`, `/404`).
- `src/components/*.astro` — Logo, Nav, Footer, ProductCard, AlpenglowHero, Mountains, LegalPage.
- `src/layouts/Layout.astro` — shared `<head>` + page chrome.
- `src/config/site.ts` — single source of truth for contact details (email, phone). Pages read from
  here; the build assertions verify the values flow through.
- `/privacy` and `/terms` carry the 10DLC SMS compliance copy — don't drop the STOP/HELP, "do not
  share or sell", or Telnyx clauses (the test suite enforces them).

## Testing

Standard interface (see `scripts/test_runner.sh`); all modes run the build + assertions
(`scripts/check-build.mjs`) since the build is fast:

```
bash scripts/test_runner.sh            # full (run before every PR)
bash scripts/test_runner.sh --smoke    # same checks, smoke label
```

Results are written to `test_logs/latest_summary.json` — read that, don't parse raw output. Add new
assertions to `scripts/check-build.mjs`. Also run `npm run check` (astro check, 0 errors expected).

## Dev server — agent workflow (Astro 7)

Astro 7's dev server is agent-aware. It detects coding agents via the `am-i-vibing` package; in an
agent session `detectAgenticEnvironment().type === "agent"`, so a plain `astro dev` **auto-runs in
the background and returns control** (with JSON logging) instead of hanging the session. Humans
running `npm run dev` in a normal terminal still get the interactive foreground server — unchanged.

Background server commands (also wired as npm scripts):

| Command | npm script | Purpose |
|---|---|---|
| `astro dev --background` | `npm run dev:bg` | Start detached; returns immediately. |
| `astro dev status` | `npm run dev:status` | Is a server running? (pid, uptime) |
| `astro dev logs [--follow]` | `npm run dev:logs` | View background server logs. |
| `astro dev stop` | `npm run dev:stop` | Stop the background server. |

Add `--json` to any of these for machine-readable output (one JSON object per line:
`{message, label, level}`). In an agent session JSON logging is on by default.

Runtime files live in `.astro/` and are gitignored: `dev.json` (lockfile), `dev.log`, plus
`settings.json` (telemetry). The tracked `.astro/*.d.ts` / `*.mjs` files are generated content types
— regenerated by `astro sync`/`check`/`build`.

**Gotcha:** only one background server per port (4321). Starting a second, or restarting before the
previous one fully exits, fails with *"Dev server process exited before becoming ready."* Recover
with `npm run dev:stop` (or `astro dev stop`) before starting again; check with `npm run dev:status`.
